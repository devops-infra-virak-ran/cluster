# Kubespray

Turns the EC2 instances Terraform created into a Kubernetes cluster.

Kubespray is **not vendored here**. Playbooks run from the official container
image, `quay.io/kubespray/kubespray:v2.31.0`, with a workspace's inventory and
this directory's `group_vars/` bind-mounted in. The host needs Docker and an
SSH key — no Ansible, no Python, no virtualenv — and an upgrade is a one-line
tag bump instead of a merge against thousands of upstream commits.

```
run.sh                          container wrapper — every playbook goes through it
group_vars/
  all/
    all.yml                     runtime, access, download strategy
    aws.yml                     what AWS integration this cluster has, and what it does not
    etcd.yml                    etcd tuning
  k8s_cluster/
    k8s-cluster.yml             version, CIDRs, hardening, kubelet reservations
    k8s-net-calico.yml          CNI encapsulation
    addons.yml                  what Kubespray installs
storage/gp3-storageclass.yaml   the default StorageClass (`make storage`)
inventory/<workspace>/          generated by `make apply` — gitignored
```

The directory names under `group_vars/` are Ansible group names, exactly. A
file named `k8s-cluster.yml` at the `group_vars/` root would map to a group
called `k8s-cluster`, which does not exist — so it would be ignored, with no
error and no applied settings.

## Deploy

```bash
make kubespray-pull   WORKSPACE=dev     # pin the image (~135 MB)
make kubespray-ping   WORKSPACE=dev     # every node answers through the bastion
make kubespray-deploy WORKSPACE=dev     # 20-40 minutes
```

Or `make cluster-up WORKSPACE=dev` for all of it, Terraform included.

`run.sh` takes the workspace as its first argument and is usable directly:

```bash
kubespray/run.sh dev cluster.yml
kubespray/run.sh dev scale.yml --limit=worker3
kubespray/run.sh dev shell                       # poke around inside the image
```

The playbooks are idempotent. Change something in `group_vars/` and rerun; only
the drift is applied.

## One inventory per workspace

Terraform writes `inventory/<workspace>/inventory.ini`, for the same reason
state and tfvars are per-workspace: `make kubespray-deploy WORKSPACE=prod` must
not be able to pick up dev's addresses. `run.sh` also re-reads the `Workspace:`
line Terraform stamped into the file and refuses a mismatch.

### How the mounts line up

| Host | Container | Why |
| --- | --- | --- |
| `inventory/<workspace>/` | `/inventory` | the inventory, and where artifacts come back |
| `group_vars/` | `/inventory/group_vars` (ro) | Ansible loads group_vars from beside the inventory file; one shared copy rather than one per workspace |
| your SSH key | *the same absolute path* | the inventory names an absolute key path for both the node connection and the bastion `ProxyCommand` — mounting it elsewhere breaks both |
| `.known_hosts` | `/tmp/.ssh/known_hosts` | a host key accepted once stays accepted |

The container runs as your UID, so `artifacts/admin.conf` comes back owned by
you and `scripts/kubeconfig.sh` can read it. This is also why the Terraform
template calls `pathexpand()` on the key path: a `~` would resolve to `/root`
in here and the first SSH connection would fail.

## Getting kubectl access

```bash
make kubeconfig WORKSPACE=dev
export KUBECONFIG=~/.kube/config-dev
```

`kubeconfig_localhost: true` leaves an admin kubeconfig in
`inventory/<workspace>/artifacts/admin.conf` pointing at the control plane's
**private** IP, which resolves nowhere outside the VPC. The script rewrites the
server to `127.0.0.1` and forwards that port through the bastion. TLS
verification stays on — kubeadm puts `127.0.0.1` in the apiserver certificate.

`kubectl_localhost: true` also fetches a kubectl matching the cluster, to
`inventory/<workspace>/artifacts/kubectl`. Use it: kubectl supports one minor
version of skew either side of the apiserver, and this cluster is on 1.35.

## Day-two operations

| Task | Command |
| --- | --- |
| Add a node | raise `worker_count`, `make apply`, `make kubespray-scale NODES=worker3` |
| Remove a node | `make kubespray-remove NODES=worker3`, then lower the count and apply |
| Upgrade Kubernetes | `make kubespray-upgrade` |
| Uninstall Kubernetes, keep the machines | `make kubespray-reset` |

Upgrading means bumping **both** `KUBESPRAY_VERSION` in the Makefile and
`kube_version` in `group_vars/k8s_cluster/k8s-cluster.yml` to a supported pair,
then `make kubespray-pull`. One minor version at a time (1.33 → 1.34 → 1.35):
skipping one breaks the kubelet/apiserver skew policy, and the upgrade fails
partway with a cluster left on mixed versions.

## What this cluster does not have

**No cloud controller manager.** Kubernetes removed the in-tree AWS provider in
1.31, and Kubespray v2.31.0 has no AWS replacement —
`roles/validate_inventory/tasks/main.yml` accepts `external_cloud_provider` only
from `hcloud, huaweicloud, oci, openstack, vsphere, manual`. So
`Service type=LoadBalancer` stays Pending forever: nothing in the cluster can
create an ELB. Ingress is the ALB that Terraform already points at the NodePort
range. `group_vars/all/aws.yml` has the long version.

**No storage until you ask for it.** `make storage` installs the upstream EBS
CSI driver and a gp3 default StorageClass. Kubespray's own `aws_ebs_csi_enabled`
is off because it deploys `docker.io/amazon/aws-ebs-csi-driver:latest` from a
Docker Hub repository that stopped being updated at v1.6.2 in 2021. Until
`make storage` runs, every PVC stays Pending.

## Gotchas

- **The inventory is generated.** `make apply` rewrites it. Per-node overrides
  belong in `group_vars/` or a `host_vars/` file, not in `inventory.ini`.
- **The bastion IP changes when the bastion is replaced.** Run
  `make inventory WORKSPACE=<ws>` before any playbook if that happens, or every
  connection fails at the `ProxyCommand`.
- **The image tag is the version.** Nothing warns you when `kube_version` and
  the tag disagree; the run just fails partway. v2.31.0 carries checksums for
  1.33.0 through 1.35.4 and refuses anything else.
- **Pod and service CIDRs must not overlap the VPC.** `10.233.0.0/18` and
  `10.233.64.0/18` sit clear of `10.0.0.0/16`. Widen the VPC and move these
  first.
- **Swap must be off, and stay off.** Cloud-init disables it and comments it out
  of `/etc/fstab`; a node that comes back with swap on will not join.
- **`download_run_once: true`** means the first control-plane node fetches every
  binary and image and pushes them to the others. It needs disk headroom — that
  is why the control-plane root volume is 50 GB.
- **Do not pass these variables with `-e`.** Extra-vars are the highest
  precedence tier in Ansible and would override Kubespray's own host_vars and
  role logic.
